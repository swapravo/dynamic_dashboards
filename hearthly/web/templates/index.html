The evolution of dashboards

From reports someone emails you on Monday, to an AI agent that explores the data with SQL and builds the dashboard while you watch. Same company, same database: only the way we ask questions changes.

See the classic dashboard Open the live AI workspace →
1
1990s – 2000s

Static reports

What it looks like
A fixed PDF or spreadsheet, emailed every Monday.
Who builds it
IT or a central BI team.
2–4 weeksfor a new question
  • Only answers questions asked months ago
  • Stale by the time it is read
  • No drill-down: “why?” means a new request
2
2010s

Interactive BI

What it looks like
Self-serve dashboards with filters and drill-down.
Who builds it
Analysts, in a BI tool; business users filter.
Daysfor a new question
  • Filters only explore what the model anticipated
  • Dashboard sprawl and conflicting numbers
  • A new metric still needs an analyst
3
Early 2020s

Natural-language query

What it looks like
Type a question, get one chart back (text-to-SQL).
Who builds it
Anyone asks; the tool writes one query.
Minutesfor a new question
  • One-shot answers: no investigation or follow-through
  • Inconsistent definitions erode trust
  • Can’t build or maintain a dashboard
4
Now

Agentic dashboards via MCP

What it looks like
An AI agent explores with SQL, uses governed metric definitions, and builds or edits live dashboards.
Who builds it
The business user and an AI agent, inside guardrails set by the data team.
~1 minutefor a new question
  • Needs guardrails: read-only access, a semantic layer, audit logs
  • Answers still need human judgement and verification
  • Quality depends on data quality

Time-to-answer figures are illustrative, for discussion, not benchmarks.
